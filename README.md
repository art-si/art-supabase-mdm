## 项目定位

亿企工场 MDM 为跨业务域提供稳定的资料身份与生产基础。一方面汇总 Platform、HR、TMS、VMS、SMIS 和 MDM 的权威主档，支持查询、完整度核对和来源追溯；另一方面维护本应用拥有的物料、仓储、往来、生产及工程配置，供 SCM、MES、WMS 等应用通过受控契约引用。

本仓维护 MDM 页面、领域 API、类型与业务规则。认证、租户、动态菜单、按钮权限、布局、主题、公共组件和 Supabase 公共运行时由 [`art-supabase-pro`](https://gitee.com/art-si/art-supabase-pro) 提供。

| 领域 | 已有能力 |
| --- | --- |
| 目录与治理 | 五类治理域、24 类独立主档及员工任职/客户地址两类关系对象；服务端分页、组合筛选、完整度、来源与详情核对 |
| 质量与变更 | 质量问题检测、分派与整改，变更申请及审核发布，重复候选人工评审、黄金记录来源映射、分发状态与失败重试 |
| 物料主数据 | 类型、分类、属性组、计量单位、编码规则、物料档案及分类驱动的物料描述 |
| 仓储基础 | 仓库、库区、库位与三维查看，批次、包装、序列号、预留、移动类型、出库规则及供应链编码规则 |
| 往来与结算 | 客户、供应商、项目、结算方式、收款条件、付款条件与付款用途 |
| 生产资源 | 部门/产线、生产人员、法定假日、工厂日历、轮班排班、人员工作中心安排、作业模板与工作中心 |
| 工程与工艺 | 组件类型、BOM 维护与结构查看、生产设备、电子作业指导书、工序/工位/控制码/活动公式与工艺路线 |

| 业务配置 | 单据类型、业务类型及其菜单适用范围、默认规则、专用字段与生产排包参数配置 |

## 近期完善

- 物料档案按类型或分类编码，分类属性共同生成物料描述；共用写入规范处理空值，保留服务端唯一性和字段校验。
- 单据类型支持多个菜单功能，业务类型必须位于所属单据类型范围内。修改默认归属时展示影响并确认，避免同租户同功能出现重叠默认项。
- BOM、组件类型、配件加工和 MES 工单衔接；识别记录可继续校对，预览与业务清单分开保存。识别结果需要人工确认，不等同于已生成物料或工单。
- 生产日历、排班、工作中心和工艺配置复用平台选择器、配置式表单、详情展示与加载/错误重试，业务删除使用共享引用防护。

## 数据所有权与办理顺序

统一目录是读取和治理入口。员工、客户、车辆等来源主档继续由所属应用维护；治理申请经受控流程产生变更及分发记录，不按名称或编号自动合并记录，也不覆盖历史业务快照。MDM 自有基础资料在对应维护页面办理。

```text
组织 / 人员 / 物料 / 仓库等主数据
  → BOM、工艺路线与生产日历
  → 工作中心、人员设备与执行规则
  → MES 工单、排程、派工与报工
  → WMS 领退料、完工入库与库存追溯
```

跨模块办理前应启用物料与仓库、核对组织及项目/施工号。MES 领料仓库的业务范围需包含「拣货」，仓库类型与工单类型匹配；启用库位时还需维护可用库位。生产实绩由 MES 记录，库存变化由 WMS 办理，MDM 不生成虚构实绩。

## 本地开发

要求 Node.js `>= 22.13.0`、pnpm `>= 11.28.2`。

```powershell
pnpm install
pnpm dev
```

默认地址为 `http://localhost:3017`。在主仓中开发时位于 `modules/art-supabase-mdm`；独立克隆时通过 `package.json` 中固定版本的 `art-supabase-pro` 依赖获取平台运行时。也可通过 `ART_SUPABASE_PLATFORM_ROOT` 指向本地平台。

平台与应用环境配置由共享 Vite 工厂合并；部署前按自己的环境核对后端和公共路径，浏览器端仅使用公开配置。

| 命令                  | 用途                                  |
| --------------------- | ------------------------------------- |
| `pnpm boundary:audit` | 检查主子仓与跨领域边界                |
| `pnpm typecheck`      | 通过共享模块入口执行类型检查          |
| `pnpm check`          | 边界、UI、类型、ESLint 与本仓单元测试 |
| `pnpm build`          | 类型检查并构建到 `docs/`              |
| `pnpm preview`        | 预览构建结果                          |

`docs/` 是静态发布产物。发布路径由环境中的 `VITE_BASE_URL` 控制。业务菜单由服务端下发，访问路径与 `src/views/**/index.vue` 逐段对应。

## 协作与权限

- 子仓先提交并推送，再在主仓更新 `modules/art-supabase-mdm` 指针。通用组件和工具复用主平台；跨领域读取使用最小字段、租户隔离的 API/RPC 契约。
- 普通用户仅访问本租户及授权资料。平台超级管理员的全部/指定租户读取与写入目标沿用主平台规则；前端可见性不能替代 RLS 和服务端权限。
- 新增、编辑、复制、绑定、导入和状态变更分别受业务权限约束。删除前检查引用，仍被业务使用的资料不能通过级联清理历史记录。
- AI 只读能力面向已启用普通用户；按对应 `Add` 权限创建本租户主数据。其他 AI 业务修改、配置、发布和受控写入需平台超级管理员授权，审计记录不能绕过业务权限。

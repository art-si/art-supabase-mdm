# MDM views

MDM 维护跨业务域主数据的统一目录、质量治理、四眼变更、黄金记录和可靠事件交付。来源应用仍是业务主档的权威写模型；治理中心只通过数据库授权 RPC 生成审批记录和 Outbox 指令，由来源适配器幂等执行，避免双写。

## 配件加工清单

工程主数据下的“配件加工清单”使用 `mdm-accessory-processing` 私有存储桶。统一 DOCX 模板、PNG/JPG/WebP、PDF 和 DOCX 原件可上传；浏览器将前三页栅格化供识别，文件上限为 20 MB。识别返回物理表格行及长度/数量组合，系统将每个组合展开为独立加工件，并把该行草图裁剪到单独的租户文件路径。看不清的草图需人工补传。

租户用户可在本租户识别、校对、保存和生成配件加工清单。页面按 `MdmAccessoryProcessing:SaveDraft` 及各阶段生成按钮权限显示操作；保存与生成 RPC 同时校验登录身份、对应权限和租户范围。已有的租户角色只要有该页面权限，就获授这五项操作权限；后续角色可通过角色管理配置。清单与加工件表的直接写入仍受 RLS 限制，业务写入须走带校验的 RPC。识别接口要求 `MdmAccessoryProcessing:Recognize`，仅接受调用者上传到该私有桶 `page` 目录的短时签名图片地址；`mdm_validate_accessory_ocr_pages` 只授予服务角色执行。

识别结果按原表行分组，行内每种长度仍是独立加工件。各行可折叠，摘要显示名称、加工件数和长度组合；默认只展开带行级核对提示的分组。拥有保存权限的租户用户可使用 `ArtForm` 校对字段，并通过公共 `ArtUploadImage` 为每件加工件补传、预览或移除草图。页面把“我的识别记录”和“配件加工清单数据列表”分开：前者读取当前登录者在当前租户范围内的 `ai_artifact_review` 审计记录，刷新后可打开识别文字，并通过审计记录的页图索引在私有桶内重新签发原件和逐件草图地址；后者将已保存的 `mdm_accessory_processing_list` 展开为逐件业务数据行，列出独立图片、项目/图纸、原表行、物料编码/名称/规格、尺寸、数量、单位、材质颜色、备注、类型、来源和分类，支持搜索及分页。文件暂时无法恢复时仍显示识别文字并提示预览失败，不把预览当成已保存的业务清单。

平台超级管理员可在选定租户的识别记录中接手其他用户上传的结果；租户用户的识别记录仍只显示本人上传的内容。重新打开识别记录或草稿时，补传草图沿用原件上传组，保存时可通过原件与草图的同组校验。识别记录不会自动进入业务数据列表，校对后必须点击保存；生成前必须补齐每件独立草图。关联已有项目时自动带出该项目客户；清除项目关联后才可选择其他客户，新建项目时需选项目客户。项目归属 RPC 的可空 UUID 参数必须传 `null`，不能传选择框清空时产生的空字符串。

保存 RPC 为每件加工件分配稳定物料编码 `ACC-<加工件 ID 的完整 32 位十六进制值>`，并持久保存规格型号、基本单位、物料类型、物料来源及物料分类。默认选择目标租户的“配件”“半成品”“PC”和“自制”；没有 PC 单位的租户回退到“件”。这些值须在目标租户有效，页面校对时可逐件修改。保存只建立清单数据；生成物料编码、项目 BOM 和生产工单分别由独立授权按钮调用 `mdm_generate_accessory_processing_stage`，并按 `draft → materials_ready → bom_ready → generated` 顺序幂等推进。原有 `MdmAccessoryProcessing:Generate` 一键入口在同一事务内完成尚未执行的步骤。BOM 阶段按项目名称唯一匹配现有项目，或在指定客户后创建项目；再建立项目父物料和生产用途 BOM。生产工单按每件加工件单独建立，`sketch_path` 直接保留在工单记录中。项目编码 `PJACC<清单 ID 的完整 32 位十六进制值>`、加工单号 `JG-<加工件 ID 的完整 32 位十六进制值>` 均不会截断碰撞；开始生成后清单只读。

验证记录：2026-09-28 数据库事务回滚样例确认同一原表行的 2.7 m 和 4.8 m 被拆为 2 个加工件、2 个不同物料编码、2 个 BOM 子项和 2 张生产工单；重复执行每个阶段没有增生记录，且 2 张工单的图片路径均与对应加工件相同。`ai-accessory-processing-contract.test.ts` 覆盖拆分及无效行。专用图片校验 RPC 仍只允许服务角色执行。

同日又用已有的 11 件识别记录、实际保存的 11 张独立草图，在模拟平台超级管理员的事务中执行“保存 → 一键生成”：得到 1 张清单、11 件加工件、11 条 BOM 子项和 11 张带对应草图路径的工单；事务回滚后业务表仍为 0 条。模拟平台超级管理员的 RLS 查询可读取该租户的识别记录及草图，支撑普通用户识别后交接保存的流程。

2026-09-28 租户权限调整后，以非平台超级管理员的租户账号模拟登录，在事务中执行“保存 → 一键生成”：得到 1 张清单、11 件加工件和 11 张带独立草图的生产工单；回滚后原有业务清单数保持 2 条。该账号具有保存和生成权限，租户范围判断对本租户返回真、对其他租户返回假。项目和客户的读取策略仅开放给本租户且具有配件清单保存权限的用户。

2026-09-28 模型故障核查：两次三页 PDF 识别先遇到 OpenAI 通道 401，随后 NVIDIA 的 `meta/llama-3.2-90b-vision-instruct` 在约 120 秒超时。平台特性配置改用 `meta/muse-glimmer-30b` 视觉模型，不再配置 90B 回退；识别函数优先使用配置指定的 NVIDIA 通道，并为该模型使用低推理强度。以用户提供的中文雨篷样张进行真实 NVIDIA API 测试：单页完整 JSON 在约 24 秒返回并通过加工件契约验证，三图完整 JSON 在约 35 秒返回并识别出 6 个有内容行，其中第一行的 2.7 m 和 4.8 m 保持为两个加工件。模型未给出可信草图边界时返回 `null`，仍需在生成前人工补图及核对；实际三页业务 PDF 的端到端复测需使用登录会话完成。

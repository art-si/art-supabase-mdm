# MDM views

MDM 维护跨业务域主数据的统一目录、质量治理、四眼变更、黄金记录和可靠事件交付。来源应用仍是业务主档的权威写模型；治理中心只通过数据库授权 RPC 生成审批记录和 Outbox 指令，由来源适配器幂等执行，避免双写。

## BOM 维护与删除

BOM 维护列表只允许勾选有删除权限且处于设计状态的 BOM。批量删除通过 `mdm_delete_boms(uuid[])` 在一次事务内逐条调用 `mdm_delete_bom(uuid)`；任一条失效或被业务引用时整批回滚。单条与批量删除共用服务端的按钮权限、当前租户范围和设计状态校验。删除函数先移除组件，再删除父 BOM，保证组件删除触发器能读取到父项；配件加工清单仍引用该 BOM 时明确拒绝删除。

2026-09-30 在项目 `ckbftoopuyophiebamwy` 的回滚事务验证了平台全部租户、平台选定租户、普通用户本租户删除，以及普通用户伪造跨租户请求被拒绝、非设计状态和业务引用被拒绝、批量失败整批回滚。应用函数后重复验证，BOM 与组件数量保持 15/60，未留下测试删除。

## 配件加工清单

工程主数据的“配件加工清单”以项目、图纸和独立加工件为主线。页面沿用业务工作区头部、分割面板、`ArtSectionCard` 和 `ArtTable`：左侧树按系统项目和图纸筛选，支持搜索、展开及面板拖拽收缩；右侧展示逐件明细。表格使用 `ArtTable` 内置分页，默认每页 20 件；宽分栏显示总数、页码、每页条数和跳页，窄分栏按实际宽度收紧，分页栏始终留在明细面板底部；换页后序号延续且滚动回顶部。图片列保留足够宽度完整展示 64 × 56 的预览或待补图占位。窄屏时操作按钮换行，筛选与搜索保持可见。选中记录后说明置灰操作的业务条件，并提供“查看待编码件”入口。专注模式隐藏概览，按 Esc 退出。图纸项目名称保留识别或手工录入值，系统项目通过 MDM 销售项目关联，两个字段独立保存。

手工新增、复制、编辑和删除经过各自的 `MdmAccessoryProcessing` 按钮权限与租户范围校验。手工清单的 `source_path` 为 `null`；上传图片与 MDM 物料编码共用 `ArtUploadImage`、资源库和 `sys_attachment`/`attachments` 存储。AI 识别支持 PNG/JPG/WebP、PDF、DOCX 和统一模板，原件存入 `mdm-accessory-processing` 私有桶，浏览器最多栅格化前三页、文件上限 20 MB；同一原表行的不同长度拆为独立加工件。识别预览可逐件校对、移除错误行或重新识别；名称、展宽、长度、数量和基础物料属性核对后，点击“确认并保存清单”才进入业务列表。租户用户可识别并查看本人识别审计记录；保存 AI 结果及后续修改、生成物料、BOM 或工单均按对应按钮权限与租户范围控制，无须平台超级管理员身份。

保存草稿时 `material_code` 与物料描述为空，编码状态为待编码。默认物料类型为“半成品”、来源为“自制”、分类为“配件”，单位优先 PC/件；用户可按目标租户有效选项调整。对所选待编码行，`mdm_generate_accessory_materials` 要求有效系统项目与正数展宽，沿用 MDM 编码策略创建 `mdm_material`，并将系统项目、编码、描述、图片、类型、来源、分类和编码策略回写到清单。项目不一致或属性失效时事务整体拒绝。已编码件需先通过“删除物料编码”解除关联，才可编辑并重新生成。

单选或多选“删除”先经 `MasterDataDeleteGuard` 调用 `mdm_get_accessory_delete_dependency_details` 检查加工件及其物料的入站外键，返回业务记录单号、状态和可访问的处理入口。无关联时直接显示删除确认；有引用时只显示关联明细，不出现可删除确认。旧 `mdm_accessory_work_order` 的草稿通过明确勾选和二次确认调用 `mdm_delete_legacy_accessory_order_drafts` 单独清理；MES 工单、BOM 等业务历史仍需到对应页面处理。最终删除仍由 `mdm_delete_accessory_processing_items` 复查权限、租户及引用，一批最多 100 件，任一项失败则整批回滚。“删除物料编码”保留加工件和图片并重置为待编码。删除后的服务端并发拒绝会重新检查关联明细。旧版草稿清理仅支持状态 `draft` 的指定记录，不自动处理业务历史。

“转项目 BOM”和“转生产工单”由用户分别点击，互不自动触发。前者要求清单全部加工件已编码且关联系统项目，调用 `mdm_generate_accessory_processing_stage(..., 'bom')` 创建项目 BOM；再次调用返回原 BOM，不重复创建。列表用 `bom_id` 显示已转状态，多清单依次执行时明确报告部分完成数量。原有一键生成及旧材料/工单阶段保留兼容权限，但数据库拒绝旧阶段执行，避免写入旧加工单表。

“转生产工单”调用 `mdm_convert_accessory_work_orders`，按所选已编码且正数展宽的加工件分别写入 `mes_work_order` 和 `mes_work_order_detail`；工单类型固定为 PP40，系统项目自动带入，计划开始日期默认为当天，完工日期必填，施工号可空且不要求预存施工段。`mes_work_order.accessory_item_id` 建立来源关联并以租户和加工件唯一约束防止重复转单。列表“是否转工单”根据未软删除的 MES 关联显示状态；有配件清单查看权限的用户可读取本租户由该清单产生的工单编号。旧 `mdm_accessory_work_order` 历史记录不充当 MES 转单状态。

数据库变更在 Supabase 项目 `ckbftoopuyophiebamwy` 通过受控 SQL 事务执行，增补了清单来源可空、加工件编码策略、图片 URL 和 MES 加工件来源关联。业务表直接写入仍受 RLS 限制；公开 RPC 为 `SECURITY INVOKER`，内部授权函数在 `app_private` 校验登录、按钮权限和目标租户。2026-09-30 的回滚事务验证了普通租户用户手工新增、保存 AI 草稿、复制与编辑、生成 MDM 物料、转项目 BOM、生成 PP40 MES 工单、批量删除、删除编码后重新生成，以及图片回填；另验证 BOM 引用阻断时整批回滚。事务结束后没有留下测试业务数据。

2026-09-30 再次用回滚事务验证了普通用户生成编码后的项目、图片和物料字段回写；旧草稿关联检查、明确清理、随后删除编码和加工件；PP40 工单与项目 BOM 分别手动转换；普通用户查看自身清单所生成工单；普通用户伪造租户头仍只看到本租户资料、平台超级管理员全部租户和指定租户范围。发现缺少展宽会违反 MES 明细约束后，在编码及转单 RPC 增加业务校验，改为可操作提示。直接数据库变更复用既有选择策略，避免增加重复的宽泛读取策略。所有测试业务记录均已回滚。

历史识别验证：2026-09-28 的真实雨篷样张在三页中识别出 6 个有内容行，同一行的 2.7 m 和 4.8 m 保持为两个加工件。草图边界不可信时返回 `null`，需要人工补图与核对；`ai-accessory-processing-contract.test.ts` 覆盖长度拆分及无效行。

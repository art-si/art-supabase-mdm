# MDM views

MDM 维护跨业务域主数据的统一目录、质量治理、四眼变更、黄金记录和可靠事件交付。来源应用仍是业务主档的权威写模型；治理中心只通过数据库授权 RPC 生成审批记录和 Outbox 指令，由来源适配器幂等执行，避免双写。

## 配件加工清单

工程主数据的“配件加工清单”以项目、图纸和独立加工件为主线。页面沿用业务工作区头部、分割面板、`ArtSectionCard` 和 `ArtTable`：左侧树按系统项目和图纸筛选，支持搜索、展开及面板拖拽收缩；右侧展示逐件明细。操作按钮、编码状态筛选和搜索框位于同一行，选中记录后说明置灰操作的业务条件，并提供“查看待编码件”入口。专注模式隐藏概览，按 Esc 退出。图纸项目名称保留识别或手工录入值，系统项目通过 MDM 销售项目关联，两个字段独立保存。

手工新增、复制、编辑和删除经过各自的 `MdmAccessoryProcessing` 按钮权限与租户范围校验。手工清单的 `source_path` 为 `null`。AI 识别支持 PNG/JPG/WebP、PDF、DOCX 和统一模板，原件存入 `mdm-accessory-processing` 私有桶，浏览器最多栅格化前三页、文件上限 20 MB；同一原表行的不同长度拆为独立加工件。租户用户可识别并查看本人识别审计记录；保存 AI 结果及后续修改、生成物料、BOM 或工单均按对应按钮权限与租户范围控制，无须平台超级管理员身份。识别记录须经人工校对并点击“保存配件加工清单”才进入业务列表。

保存草稿时 `material_code` 与物料描述为空，`code_rule_id` 指向目标租户的有效策略。默认物料类型为“半成品”、来源为“自制”、分类为“配件”，单位优先 PC/件；用户可按目标租户有效选项调整。`mdm_generate_accessory_materials` 沿用 MDM 物料编码规则生成 `mdm_material`，将编码、描述和图片关联回加工件，已生成物料的记录不能重复编辑。`mdm_generate_accessory_processing_stage(..., 'bom')` 根据已编码清单创建项目 BOM。原有一键生成及旧材料/工单阶段保留兼容权限，但数据库拒绝旧阶段执行，避免写入旧加工单表。

“转生产工单”调用 `mdm_convert_accessory_work_orders`，按所选已编码加工件分别写入 `mes_work_order` 和 `mes_work_order_detail`；工单类型固定为 PP40，系统项目自动带入，计划开始日期默认为当天，完工日期必填，施工号可空且不要求预存施工段。`mes_work_order.accessory_item_id` 建立来源关联并以租户和加工件唯一约束防止重复转单。列表“是否转工单”根据该 MES 关联显示状态。旧 `mdm_accessory_work_order` 历史记录不充当 MES 转单状态。

数据库变更在 Supabase 项目 `ckbftoopuyophiebamwy` 通过受控 SQL 事务执行，增补了清单来源可空、加工件编码策略和 MES 加工件来源关联。业务表直接写入仍受 RLS 限制；公开 RPC 为 `SECURITY INVOKER`，内部授权函数在 `app_private` 校验登录、按钮权限和目标租户。2026-09-30 的回滚事务分别验证了普通租户用户手工新增、保存 AI 草稿、复制与编辑、删除 AI 加工件、生成一件 MDM 物料、转项目 BOM、生成一张 PP40 MES 工单（包括不校验施工段的选填施工号）；事务结束后没有留下测试业务数据。权限审计、UI 审计、共享复用审计、根项目与 MDM 类型检查，以及 MDM 构建均通过。

历史识别验证：2026-09-28 的真实雨篷样张在三页中识别出 6 个有内容行，同一行的 2.7 m 和 4.8 m 保持为两个加工件。草图边界不可信时返回 `null`，需要人工补图与核对；`ai-accessory-processing-contract.test.ts` 覆盖长度拆分及无效行。
